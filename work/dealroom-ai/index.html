Dealroom.ai.

EXPLORE THE BREAKDOWN ↓
01 /

The context.

Preparing a technical proposal from a client request involves reading large documents, extracting needs, identifying ambiguity, suggesting an architecture and turning that information into something the client can explore.

MY FOCUS

Team hackathon contribution. The repo documents the architecture and early prototype; the precise division of work across team members has not yet been documented publicly.

WHAT WAS DELIVERED

Our team placed second. The repository checklist records a working document-upload and parsing flow with streamed progress; the multi-agent war room, strategies and interactive proposal remained planned at the point recorded.

VIEW GITHUB REPOSITORY ↗Repository is currently private; the link may require access.
02 /

Engineering decisions.

01

Read real inputs

Built a FastAPI intake path for PDF, DOCX and spreadsheet files, with a Next.js upload interface and parsing feedback streamed to the browser.

02

Plan the agent pipeline

Designed an analyst–architect–estimator workflow with explicit state, interactive feedback and structured decisions rather than one unbounded prompt.

03

Scope an ambitious idea

Separated working demo capabilities from the longer-term proposal and analytics vision, making it clear what was actually implemented.

03 /

What matters.

Hackathons are not just about finishing every planned feature. A good team can define an ambitious product vision, deliver a convincing core and explain what should be built next.
